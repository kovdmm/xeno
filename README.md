# Xeno-Tactic

Браузерная tower-defense игра: 8 типов башен, 200 волн, 4 сложности, способности, музыка и звуки синтезируются
на лету. Сборки нет: `index.html` подключает скрипты напрямую.

## Быстрый старт

Нужны Node.js 22+ и Yarn 1.

```sh
yarn install
yarn start                 # http://localhost:3000 (npx serve)
```

Единственный внешний ресурс в рантайме — шрифты Google и howler.js с CDN (см. `index.html`). Без сети игра
работает, но без звука и с системными шрифтами.

## Структура

| Файл           | Роль                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| `js/core.js`   | игровая логика и состояние, без DOM и цветов; события через `XT.core.on(fn)` |
| `js/render.js` | рисование на canvas (`XT.createRenderer`), частицы, эффекты, качество        |
| `js/audio.js`  | синтез музыки и звуков, микшер, плеер на howler.js                           |
| `js/i18n.js`   | тексты ru/en                                                                 |
| `js/ui.js`     | интерфейс, ввод, раскладка, игровой цикл                                     |
| `tests/`       | юнит- и характеризационные тесты (Vitest)                                    |
| `e2e/`         | скриншот-тесты canvas (Playwright)                                           |

Модули — IIFE на общем объекте `window.XT`, порядок загрузки задан в `index.html`. Идёт рефакторинг в сторону
TypeScript и ES-модулей, поэтому структура будет меняться; тесты написаны так, чтобы пережить это.

### Случайные числа

У каждой подсистемы свой поток: `XT.rng.core`, `XT.rng.fx` (рендер), `XT.rng.audio`. Если поток не задан, берётся
`Math.random`. Это нужно, чтобы косметика (частицы, тряска) не сдвигала симуляцию, а тесты были воспроизводимы.
В новом коде используйте `rand()` модуля, а не `Math.random()`.

## Тесты

```sh
yarn test            # Vitest: ~120 тестов, около 30 с (почти всё время — синтез звуков в audio)
yarn test:watch      # то же в режиме наблюдения
yarn test:visual     # Playwright: скриншоты canvas
yarn test:all        # оба набора подряд
```

### Vitest (`tests/`)

Скрипты `js/*.js` грузятся в изолированный `node:vm`-контекст без браузера (`tests/helpers/load.js`):

- каждому потоку `XT.rng.*` задан сид, а глобальный `Math.random` в песочнице **бросает ошибку**, то есть любое
  обращение мимо `XT.rng` обнаруживается сразу;
- `loadXT(["core"], { seed, globals })` возвращает `XT`; `run(core, seconds)` крутит симуляцию шагом 25 мс, как
  игровой цикл.

| Файл                   | Что проверяет                                                                                                         |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `tests/core.test.js`   | таблицы данных, статы, цены улучшений, pathfinding, `placeCheck`, экономика, 200 волн, способности                    |
| `tests/audio.test.js`  | композиция, все рецепты эффектов, микшер (слияние, интервалы, бюджет), лазер, музыка; на фейковом Howl                |
| `tests/i18n.test.js`   | ключи ru/en совпадают, плейсхолдеры, все ключи из HTML и `ui.js`, коды ошибок core                                    |
| `tests/render.test.js` | прогон 45 волн на заглушке 2D-контекста: не падает, не оставляет мусор в состоянии ctx; рендер не влияет на симуляцию |

Golden-тест core хранится в `tests/__snapshots__/`. Если вы **намеренно** поменяли баланс — обновите:
`yarn vitest run -u`. Если не меняли, а снапшот разошёлся — это регрессия.

### Скриншот-тесты (`e2e/`)

Снимается только `#field` (canvas), чтобы не зависеть от шрифтов HUD. Время, `requestAnimationFrame` и
случайные числа подменены (`e2e/harness.js`), поэтому кадры воспроизводимы побайтно: игра не идёт сама, тест
сам продвигает её на N кадров по 1/60 с (`tick(page, n)`).

Первый запуск на машине:

```sh
npx playwright install chromium
yarn test:visual
```

Сервер (`vite` на `127.0.0.1:4173`) поднимается автоматически.

- Сцены (расстановка башен, волны) лежат в `e2e/scenes.js`, сами проверки — в `e2e/visual.spec.js`. Сцена —
  функция от `XT.core`; она сериализуется в страницу, поэтому не должна замыкаться на переменные модуля.
- **Эталонные снимки зависят от платформы** (`*-win32.png` и т. д.). Эталоны для другой ОС или CI нужно
  сгенерировать там же: `yarn test:visual:update`.
- Если картинка изменилась намеренно: `yarn test:visual:update`, затем **просмотрите** изменённые PNG в
  `e2e/visual.spec.js-snapshots/` перед коммитом.
- При падении подробности и дифф-картинки — в `test-results/` и `playwright-report/` (в git не попадают;
  `npx playwright show-report`).

### Добавить сцену

1. Опишите расстановку в `SCENES` (`e2e/scenes.js`).
2. Добавьте `test(...)` в `e2e/visual.spec.js`: `scene(page, "имя", кадры)`, затем `shot(page, "имя-снимка")`.
3. `yarn test:visual:update`, проверьте PNG глазами.

### Регрессия «музыка задваивается»

`e2e/music-autoplay.spec.js` и `e2e/music-blocked.spec.js` проверяют на **настоящем howler.js** (берётся из
`node_modules`, та же версия 2.2.4, что и на CDN), что при любых изменениях громкости музыки играет ровно одна
копия цикла: качание ползунка, переход через 0 и обратно, изменение во время синтеза и декодирования, сохранённая
громкость 0, настоящий диалог настроек, заблокированный автозапуск (до первого клика). Фейковый Howl в vitest
этого не ловит, потому что загружается мгновенно, а реальный — асинхронно и с очередью разблокировки звука.

## Playwright MCP для Claude Code

`.mcp.json` в корне подключает `@playwright/mcp`: Claude Code в этой папке может сам открывать игру в браузере,
кликать и делать скриншоты. Ничего устанавливать не нужно, сервер стартует через `npx`; при первом запуске Claude
Code спросит разрешение на него.

## Рабочий процесс

- Форматирование: Prettier (`printWidth: 120`, `trailingComma: all`) — `npx prettier --write <файлы>`.
- Перед коммитом: `yarn test:all`. Рефакторинг не должен менять ни поведение (golden-тест), ни картинку
  (скриншоты); если меняет — это должно быть сознательным решением с обновлением эталонов.
- Комментарии и имена в коде — на английском, как в существующем коде.

## Деплой

```sh
yarn deploy      # scp index.html, style.css, js/ на сервер (см. package.json)
```
